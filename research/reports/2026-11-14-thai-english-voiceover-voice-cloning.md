# VoxCPM2 ยังยืนหนึ่งเสียงไทยแบบเปิด แต่มีตัวเสริมที่ควรลอง

ณ 14 พฤศจิกายน 2026 ยังไม่มีโมเดล open source ตัวใดที่มีหลักฐานว่าดีกว่า VoxCPM2 "รอบด้าน" สำหรับภาษาไทย แต่มีสามตัวที่ดีกว่าเป็นรายมิติ **SiangTTS (Thai LoRA บน VoxCPM2)** อ่านไทยแม่นกว่าในการทดสอบขนาดเล็กของผู้พัฒนาเอง (CER 0.84% เทียบ 3.26% ของ base) และยังใช้เชิงพาณิชย์ได้แบบ share-alike **Fish Audio Drama 3 และ Higgs Audio v3** คุมอารมณ์ด้วย inline tag ได้ละเอียดกว่า แต่ติด licence และไม่มีตัวเลขภาษาไทยให้ตรวจ ส่วน **OmniVoice** มีข้อมูลฝึกภาษาไทยราว 10,500 ชั่วโมงและกำหนดความยาวเสียงต่อ scene ได้ตรง ๆ แต่มีรายงานว่าหยุดกลางคำและอ่านตัวเลขผิดภาษาเป็นบางครั้ง JaiTTS-v1.0 มีตัวเลขไทยที่ดีที่สุดเท่าที่ตีพิมพ์ แต่ไม่ยืนยันว่าเปิด weights จึงใช้ได้แค่ผ่าน demo ฝั่ง commercial นั้น ElevenLabs v4 นำทั้งคุณภาพและรายได้ และภาษาไทยใช้ได้เฉพาะรุ่น v3/v4 ที่ราคา $80 ต่อ 1 ล้านตัวอักษร ขณะที่ Gemini 3.8 Flash TTS และ iApp Chinda TTS ถูกกว่าหลายเท่า ข้อจำกัดใหญ่ที่สุดของงานวิจัยนี้คือหลักฐานภาษาไทยเกือบทั้งหมดเป็นตัวเลขที่ผู้พัฒนารายงานเองบนชุดทดสอบของตัวเอง และไม่มีแหล่งใดวัดว่า emotion tag ทำงานดีแค่ไหนกับข้อความไทย คำแนะนำเชิงปฏิบัติคือ ใช้ VoxCPM2 (+SiangTTS) บน Mac เป็นฐานต่อไป เพิ่ม OmniVoice สำหรับงานที่ต้องล็อกความยาว และเก็บ ElevenLabs v4 หรือ Gemini 3.8 Flash TTS ไว้สำหรับงานที่ต้องการอารมณ์จัดจ้าน โดยฟังทดสอบด้วยสคริปต์จริงก่อนตัดสินใจทุกครั้ง

## ไม่มีใครชนะ VoxCPM2 รอบด้าน แต่มีสามตัวที่ชนะเป็นรายมิติ

VoxCPM2 (OpenBMB, เมษายน 2026) เป็นจุดอ้างอิงที่แข็งแรง ตัวโมเดลมี 2B parameters ให้เสียง 48 kHz รองรับ 30 ภาษารวมไทย และทั้ง code กับ weights เป็น **Apache-2.0** ใช้เชิงพาณิชย์ได้ ([HF model card](https://huggingface.co/openbmb/VoxCPM2)) repo มี 40.6k stars และ benchmark ของทีมเองรายงาน Thai CER 0.94% เทียบ 1.92% ของ Fish S2-Pro ([GitHub OpenBMB/VoxCPM](https://github.com/OpenBMB/VoxCPM/)) ตัวเลขนี้ต้องอ่านอย่างระวัง เพราะผู้พัฒนา SiangTTS วัด base VoxCPM2 แบบ cloning ได้ CER 3.26% บน 80 prompts ด้วย ASR judge คนละตัว ([SiangTTS card](https://huggingface.co/dubbing-ai/SiangTTS-VoxCPM2-Thai-LoRA)) ความต่างสามเท่าระหว่างสองแหล่งแสดงว่าตัวเลข CER ข้ามแหล่งเทียบกันตรง ๆ ไม่ได้

ศูนย์กลางของงาน fine-tune ภาษาไทยย้ายจาก F5-TTS (ปี 2025: F5-TTS-THAI, ThonburianTTS, OpenJaiTTS) มาเป็นตระกูล VoxCPM (ปี 2026: JaiTTS, SiangTTS) โมเดลไทยฐาน F5 มีจุดอ่อนร่วมกันเรื่องข้อความยาว ซึ่งวัดได้ชัด: ThonburianTTS ให้ผลลัพธ์ที่ใช้ไม่ได้บนประโยค 16–30 วินาที และ OpenJaiTTS มี CER พุ่งจาก 4.78% เป็น 12.63% เมื่อข้อความยาวขึ้น ([JaiTTS paper](https://arxiv.org/html/2604.27607v2), [OpenJaiTTS card](https://huggingface.co/JTS-AI/OpenJaiTTS-v1.0))

ประเด็นที่สองคือ OmniVoice งานวิจัย Wayu-Paxa (กันยายน 2026) ซึ่งใช้ OmniVoice เป็น teacher สังเคราะห์เสียงไทย เป็นหลักฐานอิสระชิ้นเดียวที่ตรวจพฤติกรรมไทยของมันละเอียด และผลออกมาปนกัน: speaker similarity สูงสุดในกลุ่ม (0.899) แต่ CER 4.6% แย่กว่า Gemini 3.1 Flash TTS (3.3%) และมี pause ตกกลางคำไทย 5.2% เทียบ 1.9% ของ Gemini ([arXiv 2609.03502](https://arxiv.org/pdf/2609.03502)) หน้า "Open TTS Leaderboard (Thai)" บน paperswithcode.co ระบุ OmniVoice อยู่อันดับแรกด้วย WER 1.28 แต่อ่านได้เฉพาะ metadata ไม่เห็นวิธีวัดหรืออีก 5 รายการ จึงไม่รู้ว่า VoxCPM2 อยู่ในตารางนั้นหรือไม่ ([paperswithcode.co](https://paperswithcode.co/benchmark/open-tts-leaderboard-thai)) สรุปคือ **ไม่มีการเทียบ OmniVoice กับ VoxCPM2 บนภาษาไทยแบบตัวต่อตัวจากแหล่งใดเลย**

ประเด็นที่สามคือ licence ของ Higgs v3 ซึ่งอ่านผิดง่าย sidebar ของ repo แสดง Apache-2.0 แต่ใช้กับ code และสาย v2 เท่านั้น weights ของ v3 อยู่ใต้ Boson Higgs Audio v3 Research and Non-Commercial License ซึ่งห้ามใช้ใน production หรือผลิตภัณฑ์โดยไม่มี commercial licence ([HF](https://huggingface.co/bosonai/higgs-audio-v3-tts-4b), [GitHub](https://github.com/boson-ai/higgs-audio)) ส่วน Fish นั้น API ที่ให้บริการ TTS/cloning แบบ hosted ต้องขอ licence แยกเสมอ และงานพากย์ส่งลูกค้าได้รับการยกเว้นไว้ ([LICENSE](https://github.com/fishaudio/fish-speech/blob/main/LICENSE)) ถ้าใช้ในนามองค์กรที่รายได้เกินเพดาน USD 500,000 ทั้งสองตัวนี้ใช้ไม่ได้โดยไม่เจรจา licence

โมเดลดังอีกหลายตัวตกรอบเพราะไม่ระบุภาษาไทยบนหน้าหลัก ได้แก่ Chatterbox Multilingual V3 (23 ภาษา), Fun-CosyVoice 3, IndexTTS-2.5, XTTS-v2, GPT-SoVITS, Zonos, Kokoro, NeuTTS, OpenVoice V2 และ Orpheus ([Chatterbox](https://github.com/resemble-ai/chatterbox), [CosyVoice](https://github.com/FunAudioLLM/CosyVoice), [IndexTTS](https://github.com/index-tts/index-tts), [XTTS-v2](https://huggingface.co/coqui/XTTS-v2)) ตัวเหล่านี้ยังมีประโยชน์สำหรับ narration ภาษาอังกฤษ โดยเฉพาะ Chatterbox (MIT) และ IndexTTS-2.5 ที่คุมอารมณ์ได้ละเอียดที่สุดในฝั่ง open

## การคุมอารมณ์ในภาษาไทยยังเป็นจุดบอดของหลักฐานทั้งวงการ

ระบบชั้นนำใช้กลไกคุมอารมณ์หกแบบ: inline tag, คำสั่งภาษาธรรมชาติ, SSML style preset, emotion parameter แบบ enum, emotion reference audio หรือ vector และ slider ความเข้ม แบบ free-text ยืดหยุ่นที่สุดแต่ผลไม่คงที่และขึ้นกับเสียง ส่วนแบบ preset หยาบกว่าแต่ทำซ้ำได้ ข้อเท็จจริงที่สำคัญที่สุดสำหรับผู้ใช้ไทยคือ **ไม่มีแหล่งใดวัดความน่าเชื่อถือของ emotion control บนข้อความไทย** คำว่า "รองรับ" ในตารางข้างล่างจึงหมายถึง "ภาษารองรับ" บวก "มีกลไกควบคุม" ไม่ใช่พฤติกรรมรวมที่ผ่านการทดสอบ

หลักฐานเชิงตัวเลขชิ้นเดียวที่มีมาจาก iApp Chinda TTS และเป็นสัญญาณเตือน: เมื่อใส่ style อารมณ์ CER ขึ้นจาก 3.2% เป็น 8.3% พร้อมอัตรา style ล้มเหลว 15.0% ส่วนรุ่น Prime ลดลงเหลือ 3.9% และ 6.7% ([iApp Chinda TTS blog](https://iapp.co.th/blog/chindatts-launch)) การดันอารมณ์ในภาษาไทยจึงแลกกับการอ่านผิดที่เพิ่มขึ้น และต้องวางรอบฟังตรวจกับ generate ซ้ำไว้ใน workflow เสมอ

## จากคลิป Motion สู่เสียงพากย์: ให้เสียงกำหนดความยาว scene

pipeline มาตรฐานสำหรับคนที่มีสคริปต์แล้วคือ สร้างไฟล์เสียงหนึ่งไฟล์ต่อ scene อ่านความยาวจริงกลับมา แล้วให้ความยาวเสียงกำหนดความยาว scene ในโค้ดวิดีโอ ไม่ใช่กลับกัน สำหรับคลิปที่ export ออกมาแล้วความยาวตายตัว (เช่น Motion artifact ซึ่งไม่พบเอกสารสาธารณะว่ารองรับเสียงบรรยายในตัว) ลำดับที่ควรทำคือ แก้สคริปต์ให้พอดี, generate ใหม่ด้วย parameter ความเร็วหรือความยาว, แล้วค่อยใช้ ffmpeg `atempo` ในช่วงแคบ ๆ เป็นทางสุดท้าย จากนั้น mux เสียงเข้ากับภาพด้วย ffmpeg หรือโปรแกรมตัดต่อ ลำดับนี้เป็นข้อสรุปของงานวิจัยจากแนวปฏิบัติทั่วไป ส่วนเอกสาร ffmpeg ยืนยันเพียงว่า `atempo` เปลี่ยน tempo โดยไม่เปลี่ยน pitch ในช่วง 0.5 ถึง 100 ([ffmpeg atempo](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Audio/atempo.html))

ตรงนี้ OmniVoice มีข้อได้เปรียบเชิงปฏิบัติเหนือ VoxCPM2: มันมี `duration` ที่กำหนดความยาว output เป็นวินาทีได้ จึงไม่ต้องยืดหดเสียงทีหลัง ([OmniVoice](https://github.com/k2-fsa/OmniVoice)) ฝั่ง Remotion ใช้ `<Audio>` จาก `@remotion/media` ร่วมกับ `calculateMetadata` และ `getAudioDurationInSeconds()` เพื่อกำหนดขนาด composition จากเสียง และมี Agent Skills ทางการสำหรับ Claude Code ติดตั้งด้วย `npx remotion skills add` ([Remotion AI system prompt](https://www.remotion.dev/docs/ai/system-prompt), [Remotion Agent Skills](https://www.remotion.dev/docs/ai/skills))

จุดอ่อนของภาษาไทยอยู่ที่ timestamp WhisperX ไม่มี alignment model เริ่มต้นสำหรับ `th` และจะ error หากไม่ส่ง wav2vec2 model เฉพาะภาษาเข้าไป ([whisperX alignment.py](https://raw.githubusercontent.com/m-bain/whisperX/main/whisperx/alignment.py)) ทางออกมีสองทาง: ใช้ endpoint `with-timestamps` ของ ElevenLabs ซึ่งคืน timing ระดับตัวอักษรพร้อม `previous_text` / `next_text` เพื่อรักษา prosody ข้าม scene ([ElevenLabs API reference](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps)) หรือใช้ Montreal Forced Aligner ซึ่งมี Thai acoustic model v3.0.0 ภายใต้ CC BY 4.0 ([MFA Thai model](https://mfa-models.readthedocs.io/en/latest/acoustic/Thai/Thai%20MFA%20acoustic%20model%20v3_0_0.html)) ยังไม่มีเอกสารหรือการทดสอบว่า timestamp ระดับตัวอักษรของ ElevenLabs จัดการสระและวรรณยุกต์ไทยที่ซ้อนกันได้ถูกต้องหรือไม่

ปัญหาเฉพาะของไทยที่งานวิจัยพูดซ้ำกันคือ วรรณยุกต์, การไม่มีช่องว่างระหว่างคำ (ทำให้หยุดผิดที่), ตัวเลข และไทยปนอังกฤษ ซึ่งยังเป็นหมวดที่อ่อนที่สุดแม้ในผู้ขายไทย: iApp รายงาน CER 7.6–7.9% บน code-switching เทียบ 3.2% บนข้อความทั่วไป ([iApp](https://iapp.co.th/blog/chindatts-launch)) เทคนิคที่มีหลักฐานรองรับคือ ให้ LLM เขียนสคริปต์ใหม่ก่อนสังเคราะห์ โดยแปลงตัวเลขเป็นคำไทยและคำอังกฤษเป็นคำอ่านไทย (เช่น API เป็น เอ-พี-ไอ) แล้ว generate หลาย take เพื่อเลือกอันที่ดีที่สุด การสุ่ม best-of-K ยกความแม่นยำของ OmniVoice จาก 72.8% (K=1) เป็น 87.9% (K=118) ([arXiv 2609.03502](https://arxiv.org/pdf/2609.03502), [AI Unlocked](https://aiunlock.co/blog/ai-video-thai-voice-comparison)) และต้องฟังด้วยหูเสมอ เพราะการตรวจด้วย ASR มองไม่เห็นวรรณยุกต์ที่ผิดเมื่อ ASR "แก้ให้" เอง (ข้อนี้เป็นข้ออนุมานของงานวิจัย ไม่ใช่ผลวัด)

### M5 Max 128GB: หน่วยความจำไม่ใช่ข้อจำกัด ความพร้อมของ tooling ต่างหาก

mlx-audio (MIT, 8.2k stars) มี MLX port ของ VoxCPM2 (bf16/8bit/4bit), OmniVoice, MOSS-TTS v1.5, Higgs Audio v3, Fish Audio Drama 3 (4-bit), Qwen3-TTS และ Chatterbox Multilingual V3 พร้อม REST API แบบ OpenAI-compatible (`/v1/audio/speech`), web UI และ Whisper สำหรับตรวจ transcript ([mlx-audio](https://github.com/Blaizzy/mlx-audio)) README ของมันไม่ได้เอ่ยถึงภาษาไทยหรือชิป M5 โดยตรง และไม่มีการยืนยันว่า text frontend ภาษาไทยทำงานเหมือนต้นฉบับใน MLX port เส้นทางสำรองคือ PyTorch MPS ซึ่ง VoxCPM2 (`auto` ใช้ MPS บน Apple Silicon) และ OmniVoice (`device_map="mps"`, PyTorch 2.8.0) บันทึกไว้เอง โดย OmniVoice ต้องติดตั้ง `pynini` ผ่าน conda-forge เพราะไม่มี wheel สำหรับ macOS ([VoxCPM](https://github.com/OpenBMB/VoxCPM/), [OmniVoice](https://github.com/k2-fsa/OmniVoice))

ยังไม่รู้ว่า SiangTTS LoRA โหลดใน MLX port ได้หรือไม่ ทางที่ปลอดภัยคือใช้ package PyTorch ทางการของ VoxCPM บน MPS ตัวเลขความเร็วบน Apple Silicon ที่พบมีน้อยมาก: VoxCPM2 ผ่าน llama.cpp Metal ได้ RTF ราว 1.76 บน M4 Pro ซึ่งช้ากว่า real time ([VoxCPM](https://github.com/OpenBMB/VoxCPM/)) **ไม่มี benchmark บน M5 Max สำหรับโมเดลใดเลย** จึงต้องวัดเอง สำหรับเครื่องมือครอบ Voicebox (MIT, 58.2k stars) เป็น studio แบบ local ที่ดังที่สุดและมี MCP server ในตัว แต่ชุดภาษาที่ระบุไม่มีไทย ([Voicebox](https://github.com/jamiepine/voicebox)) ทางเลือกที่ถึงไทยได้คือ ComfyUI TTS Audio Suite ซึ่งรวม 19 engines รวม OmniVoice, MOSS-TTS, Higgs v3 และสร้างเสียงลงช่องเวลา SRT ได้ ([TTS-Audio-Suite](https://github.com/diodiogod/TTS-Audio-Suite)) และ pyVideoTrans (GPL-3.0, 19.6k stars) สำหรับงานแปลและพากย์วิดีโอที่มีเสียงพูดอยู่แล้ว ([pyVideoTrans](https://github.com/jianchang512/pyvideotrans))

### ตัวเลือกบน Azure มีจริง แต่อ่อนที่สุดตรงอารมณ์ภาษาไทย

Azure Speech มีเสียง neural ภาษาไทย แต่ persona ของ DragonHD มีเฉพาะ de-DE, en-US, es-ES, fr-FR, ja-JP และ zh-CN, DragonHDFlash รับเฉพาะข้อความจีนกับอังกฤษ และ DragonHDOmni ไม่ให้รายการ locale พร้อมเตือนว่าบาง locale ยังไม่มี HD ([Azure HD voices](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/high-definition-voices)) เอกสาร style ยกตัวอย่างเฉพาะ en-US กับ zh-CN และไม่ระบุว่า style ใดทำงานกับไทย การโคลนเสียงบน Azure ที่เข้ากับงานคลิปคือ Personal Voice ซึ่งใช้ prompt 5–90 วินาที แต่จำกัดเฉพาะลูกค้าที่ผ่านแบบฟอร์มขออนุมัติและต้องมี consent ที่บันทึกเสียง ([Personal voice overview](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/personal-voice-overview)) ส่วน Custom Neural Voice Professional เป็นผลิตภัณฑ์ brand voice ระดับองค์กร ตัวเลข third-party ระบุค่า hosting $4.04 ต่อ model-hour ซึ่งคิดเป็นราว $2,900 ต่อเดือนต่อ endpoint ([CostBench](https://costbench.com/software/ai-voice-tools/microsoft-speech/))

ข้อที่ต้องตรวจเองใน tenant มีสามข้อ: ราคาทางการ (หน้า pricing แสดง "$-" ตอนเก็บข้อมูล จึงควรใช้ Azure pricing calculator สำหรับ region Southeast Asia), รายชื่อเสียง th-TH และ style ที่รองรับ (เรียก `/cognitiveservices/voices/list` แล้วกรอง `Locale == "th-TH"`) และ locale ของ Personal Voice บทบาทที่ Azure ทำได้ดีใน pipeline นี้คือ speech-to-text ภาษาไทยสำหรับวง QA และซับไตเติล ซึ่งระบุ th-TH ไว้ชัด ([Azure language support](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=tts)) อีกทางที่เข้ากับ stack คือ self-host โมเดล Apache-2.0 อย่าง VoxCPM2 บน GPU ของ Azure เอง โมเดลต้องการ VRAM ราว 8 GB และได้ RTF ราว 0.30 บน RTX 4090 ([VoxCPM2](https://huggingface.co/openbmb/VoxCPM2)) แนวทางนี้เป็นข้อเสนอของงานวิจัย ไม่ได้มาจากเอกสารที่ทดสอบบน Azure

### โคลนเสียงตัวเองปลอดภัยที่สุด เสียงคนอื่นต้องมีความยินยอม

YouTube ระบุให้ "การโคลนเสียงตัวเองเพื่อทำ voice over หรือ dub" เป็นการใช้งานเล็กน้อยที่ไม่ต้องเปิดเผย ส่วนเนื้อหาสมจริงที่ทำให้คนจริงดูเหมือนพูดสิ่งที่ไม่ได้พูดต้องเปิดเผย ([YouTube Help](https://support.google.com/youtube/answer/14328491)) PDPA มาตรา 26 จัดข้อมูลชีวมิติเป็นข้อมูลอ่อนไหวที่ต้องได้รับความยินยอมโดยชัดแจ้ง แต่ตัวบทยกตัวอย่างเฉพาะใบหน้า ม่านตา และลายนิ้วมือ ไม่ได้ระบุเสียง ([PDPA Section 26](https://pdpathailand.com/pdpa/content_eng/article26_eng.php)) การถือว่าตัวอย่างเสียงของบุคคลที่สามเป็นข้อมูลอ่อนไหวและขอความยินยอมเป็นลายลักษณ์อักษรจึงเป็นการตีความแบบระวัง ไม่ใช่คำวินิจฉัยที่มีอยู่ งานเชิงพาณิชย์ควรปรึกษานักกฎหมาย โมเดล open source ที่รันเองไม่มีด่าน consent หรือ watermark ความรับผิดชอบจึงอยู่ที่ผู้ใช้ทั้งหมด

คำถามว่า "มีอะไรดีกว่า VoxCPM2 ไหม" เปลี่ยนรูปไปแล้วในปี 2026 คุณภาพเสียงระดับบนใกล้กันจนแทบเป็นสินค้าโภคภัณฑ์ (แปดอันดับแรกบน arena ห่างกันราว 65 Elo) สิ่งที่แยกผู้ชนะสำหรับงานไทยจึงเป็น licence, ความสามารถล็อกความยาว, และความแม่นยำของการอ่านคำยาก ซึ่งไม่มีตัวใดชนะครบทั้งสาม ทิศทางที่ชัดคือระบบนิเวศไทยกำลังรวมตัวรอบ VoxCPM: ทั้ง JaiTTS และ SiangTTS สร้างบนฐานนี้ การลงทุนเวลากับ VoxCPM2 จึงไม่เสียเปล่า และ LoRA ที่ฝึกด้วยเสียง 5–10 นาทีของตัวเองน่าจะให้ผลคุ้มกว่าการย้ายโมเดล

ช่องว่างที่ใหญ่ที่สุดไม่ใช่เทคโนโลยี แต่คือหลักฐาน ยังไม่มีใครตีพิมพ์ว่า emotion tag ทำงานกับข้อความไทยได้ดีแค่ไหน การทดสอบครึ่งวันบน M5 Max ด้วยสคริปต์จริงราว 20 ประโยค (มีตัวเลข คำทับศัพท์ และสามอารมณ์) ผ่าน VoxCPM2, VoxCPM2+SiangTTS, OmniVoice และ ElevenLabs v4 จะให้ข้อมูลที่ตรงกับงานมากกว่า benchmark ที่มีอยู่ทั้งหมด และควรทำก่อน 1 มกราคม 2027 ซึ่งเป็นช่วงที่ราคา Gemini เพิ่มเท่าตัวและ endpoint ของ OpenAI ปิดตัว
