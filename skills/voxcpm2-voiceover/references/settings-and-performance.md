# ค่าตั้ง ความเร็ว และสิ่งที่ยังไม่ได้ทดสอบ

## ค่าตั้งที่ `synth.py` ใช้

| ค่า | ใช้ | เหตุผล |
|---|---|---|
| `cfg_value` | 2.0 (`--cfg`) | ค่าที่ใช้ตลอดทั้งงานเล่านิทานและงานคลิป |
| `inference_timesteps` | 10 (`--steps`) | ความเร็วกับคุณภาพสมดุลกันดี |
| `load_denoiser` | False | ไม่ต้องโหลดโมเดลลดเสียงรบกวนเพิ่ม เพราะ reference ที่อัดในห้องเงียบสะอาดพออยู่แล้ว |
| `optimize` | False | ใช้ `torch.compile` ซึ่งใช้กับ MPS ไม่ได้ เปิดได้เฉพาะบน CUDA ด้วย `--optimize` |
| `normalize` | False (ค่าตั้งต้นของไลบรารี) | ให้เตรียมคำอ่านเองในสคริปต์ จะได้ควบคุมผลได้ |
| `retry_badcase` | True (ค่าตั้งต้นของไลบรารี) | ไลบรารีสร้างใหม่เองเมื่อความยาวเสียงผิดสัดส่วนกับความยาวข้อความ |
| seed | 7 และ 21 (`--seeds`) | ตั้งทั้ง `torch` และ `numpy` เพื่อให้รันซ้ำได้ผลเดิม |
| device | auto (`--device`) | ไลบรารีเลือก CUDA หรือ MPS เอง และตกไปใช้ CPU ถ้าไม่มี |

## ความเร็วและทรัพยากร (Apple M5 Max, MPS)

| รายการ | ค่าที่วัดได้ |
|---|---|
| ติดตั้งใหม่ด้วย `requirements.txt` | ราว 65 วินาที, venv 2.3 GB (ทดสอบ 14 พ.ย. 2026: voxcpm 2.0.3, mlx-whisper 0.4.3, torch 2.15.0) |
| เวลาโหลดโมเดล | ราว 60 วินาทีเมื่อเปิดเครื่องใหม่ และ 5–10 วินาทีเมื่อไฟล์อยู่ใน cache ของระบบแล้ว |
| take แรกของการรัน | ช้ากว่าปกติ (วัดได้ RTF 2.4) เพราะ MPS ต้อง warm up take ถัดไปจึงเร็วขึ้น |
| RTF หลัง warm up | ราว 0.6 สำหรับ clip ยาว และ 0.55–0.9 สำหรับประโยคสั้น 2–5 วินาที |
| เวลาต่อ clip | 16–28 วินาที สำหรับ clip ยาวระดับ scene ของนิทาน |
| หน่วยความจำ | สูงสุดราว 14 GB (weights เป็น bf16 แต่ถูกแปลงเป็น fp32 บน MPS) |
| CUDA | การ์ดจอ RTX 4090 ได้ RTF ราว 0.30 และใช้ VRAM ราว 8 GB ตัวเลขนี้มาจาก model card ยังไม่ได้ทดสอบเอง |

ชุดที่ทดสอบแล้ว: voxcpm 2.0.3 กับ torch 2.14.0 และ 2.15.0 บน Python 3.12

## ยังไม่ได้ทดสอบ

- **SiangTTS Thai LoRA** (`dubbing-ai/SiangTTS-VoxCPM2-Thai-LoRA`) ผู้พัฒนารายงานว่าอ่านไทยแม่นกว่า base (CER 0.84% เทียบกับ 3.26% บน 80 prompts) weights เป็น CC-BY-SA-4.0 ซึ่งใช้เชิงพาณิชย์ได้แต่ต้อง share-alike ไลบรารี voxcpm 2.0.3 รับ `lora_weights_path` ใน `VoxCPM.from_pretrained` อยู่แล้ว แต่ `synth.py` ยังไม่มีตัวเลือกนี้ เพราะยังไม่ได้ทดสอบ
- **MLX port** ใน mlx-audio ยังไม่ได้ยืนยันว่าการอ่านภาษาไทยได้ผลเหมือนต้นฉบับหรือไม่
- **ข้อความยาวหลายประโยคในการเรียกครั้งเดียว** ที่ทดสอบแล้วยาวไม่เกินราว 100 ตัวอักษร (ประมาณ 10 วินาที)
- **Linux และ CUDA** สคริปต์รองรับแล้ว แต่ยังไม่ได้รันจริง และ `check_takes.py` ใช้ไม่ได้เพราะ mlx-whisper รันได้เฉพาะบน Apple Silicon

รายละเอียดการเทียบกับโมเดลอื่นอยู่ใน [`research/reports/2026-11-14-thai-english-voiceover-voice-cloning.md`](../../../research/reports/2026-11-14-thai-english-voiceover-voice-cloning.md)
