# พากย์เสียงด้วย VoxCPM2

VoxCPM2 คือโมเดล TTS ขนาด 2B ของ OpenBMB ให้เสียง 48 kHz และรองรับ 30 ภาษารวมภาษาไทย ทั้ง code และ weights เป็น Apache-2.0 จึงใช้เชิงพาณิชย์ได้ รันบน Mac ผ่าน MPS ได้โดยไม่ต้องส่งข้อมูลออกนอกเครื่อง

ตัวเลขและข้อสังเกตในไฟล์นี้มาจากการใช้งานจริงกับ voxcpm 2.0.3 บน Apple M5 Max ระหว่าง ต.ค. ถึง พ.ย. 2026 ได้แก่ งานเสียงเล่านิทานหลายภาษา และคลิปแนะนำผลิตภัณฑ์ยาว 45 วินาที ส่วนไหนที่ยังไม่ได้ทดสอบเองจะเขียนบอกไว้

## สิ่งที่ต้องมี

| ต้องมี | ทำอย่างไร |
|---|---|
| Python 3.12 พร้อม venv สำหรับ VoxCPM2 | `python3.12 -m venv .venv-voxcpm && .venv-voxcpm/bin/pip install voxcpm` (ทดสอบกับ 2.0.3) |
| weights ราว 5 GB | โหลดจาก Hugging Face อัตโนมัติในการรันครั้งแรก หลังจากนั้นตั้ง `HF_HUB_OFFLINE=1` เพื่อไม่ต้องต่อเน็ต |
| หน่วยความจำว่าง 16 GB ขึ้นไป | บน MPS ใช้สูงสุดราว 14 GB และจะคืนหน่วยความจำเมื่อ process จบ |
| ffmpeg และ ffprobe | ใช้ตัดเสียงเงียบ ปรับจังหวะ และต่อไฟล์ |
| venv แยกที่มี mlx-whisper (เฉพาะ Apple Silicon) | `pip install mlx-whisper` โมเดลตั้งต้นคือ `mlx-community/whisper-large-v3-mlx` |

ในคำสั่งทั้งหมดด้านล่าง ให้ตั้งตัวแปรเหล่านี้ก่อน

```bash
SKILL=<โฟลเดอร์ของ skill นี้>          # เช่น skills/voxcpm2-voiceover
VOX=<python ใน venv ที่มี voxcpm>
ASR=<python ใน venv ที่มี mlx-whisper>
export HF_HUB_OFFLINE=1               # หลังโหลด weights ครั้งแรกแล้ว
```

## เลือกโหมดก่อนเริ่ม

VoxCPM2 ทำงานคนละแบบตามสิ่งที่ส่งเข้าไป สาเหตุที่พบบ่อยที่สุดของปัญหา "สั่งอารมณ์แล้วเสียงไม่เปลี่ยน" คือใช้ผิดโหมด

| โหมด | ส่งอะไรเข้าไป | ได้อะไร | ใช้เมื่อ |
|---|---|---|---|
| **Hi-Fi clone** | ไฟล์ reference พร้อม transcript ที่ตรงทุกคำ | เสียงใกล้ต้นแบบที่สุด และพูดตามจังหวะของ reference | งานพากย์และเสียงบรรยายทั่วไป |
| **Clone + คำสั่ง** | ไฟล์ reference อย่างเดียว และใส่ `(คำสั่ง)` ไว้หน้าข้อความ | น้ำเสียงจาก reference ส่วนอารมณ์ตามคำสั่ง | ประโยคที่ต้องการอารมณ์เฉพาะ หรือพูดภาษาอื่นด้วยเสียงเดิม |
| **Voice design** | ไม่มี reference มีแต่ `(คำบรรยายเสียง)` | เสียงใหม่ตามคำบรรยาย ซึ่งแต่ละ seed จะได้คนละเสียง | ใช้สร้าง reference เมื่อยังไม่มีเสียงต้นแบบ |

- **คำสั่งในวงเล็บไม่มีผลในโหมด Hi-Fi** ถ้าต้องการอารมณ์ ให้ใส่ `--no-transcript` ส่วน `scripts/synth.py` จะไม่ยอมรับ `--style` ในโหมด Hi-Fi และจะตัดคำสั่งในวงเล็บที่อยู่ต้นบรรทัดออกพร้อมแจ้งเตือน
- ใช้ transcript เฉพาะเมื่อข้อความที่จะพากย์เป็นภาษาเดียวกับ reference ถ้า reference เป็นภาษาไทยแต่จะพากย์ภาษาอังกฤษ ให้ใช้ `--no-transcript` แล้วเสียงที่ได้จะยังเป็นคนเดิม
- เขียนคำสั่งเป็นภาษาอังกฤษ เพราะเอกสารของ VoxCPM2 รองรับเฉพาะคำสั่งภาษาอังกฤษและจีน ควรสั้น ไม่เกิน 120 ตัวอักษร และไม่ต้องใส่วงเล็บเองเมื่อส่งผ่าน `--style`

## ขั้นตอน

### 1. เตรียม reference

- อัดเสียง 10–15 วินาทีในห้องเงียบ พูดด้วยจังหวะและอารมณ์ที่ต้องการ เพราะโมเดลไม่มีพารามิเตอร์ความเร็วและจะพูดตามจังหวะของ reference ถ้าต้องการเสียงเล่าเรื่องที่ช้า reference ก็ต้องช้าด้วย
- เก็บเป็น `voices/<ชื่อ>.wav` คู่กับ `voices/<ชื่อ>.txt` ที่พิมพ์ทุกคำตามที่พูดจริง ถ้า transcript ไม่ตรงกับเสียง ผลในโหมด Hi-Fi จะเพี้ยน
- โฟลเดอร์ `voices/` และไฟล์เสียงทุกชนิดถูกกันไว้ใน `.gitignore` ห้ามบังคับ commit ไฟล์เหล่านี้
- โคลนได้เฉพาะเสียงที่เจ้าของเสียงอนุญาตแล้วเท่านั้น
- reference ที่พูดเสียงเรียบเมื่อนำไปพูดประโยคอารมณ์จัดมักจะเพี้ยน ถ้างานต้องใช้หลายอารมณ์ ควรอัด reference แยกตามอารมณ์

ถ้ายังไม่มีเสียงคน ให้สร้างด้วย voice design เขียนประโยคยาว 10–15 วินาทีลงใน `ref_line.txt` แล้วรัน

```bash
$VOX $SKILL/scripts/synth.py --lines ref_line.txt --design "warm, gentle Thai woman, storyteller, slow" \
    --seeds 1,2,3,4 --out takes_design
```

ฟังทุก seed แล้วเลือกหนึ่งไฟล์ คัดลอกไปเป็น `voices/<ชื่อ>.wav` แล้วใส่ประโยคเดียวกันลงใน `voices/<ชื่อ>.txt` ตั้งชื่อไฟล์ให้รู้ว่าเป็นเสียงสังเคราะห์ เช่น `design-narrator-warm.wav` เพราะเคยมีไฟล์ที่ตั้งชื่อว่า "human" ทั้งที่เป็นเสียงสังเคราะห์ แล้วทำให้เข้าใจผิดในภายหลัง

### 2. เตรียมสคริปต์

ใช้ไฟล์ `.txt` ที่มีหนึ่งประโยคหรือหนึ่ง scene ต่อบรรทัด บรรทัดว่างและบรรทัดที่ขึ้นต้นด้วย `#` จะถูกข้าม หรือใช้ `.json` ที่เป็น list ของข้อความก็ได้ ถ้าต้องการอารมณ์เฉพาะบรรทัด ให้ใส่คำสั่งไว้ต้นบรรทัด เช่น `(cheerful, bright and happy tone)ข้อความ` ดูตัวอย่างได้ที่ [`examples/script-th.txt`](examples/script-th.txt)

- **สร้างทีละประโยค** ประโยคที่ทดสอบแล้วยาวไม่เกินราว 100 ตัวอักษร (ประมาณ 10 วินาที) ข้อความยาวกว่านี้ในการเรียกครั้งเดียวยังไม่ได้ทดสอบ
- **ตัวเลข วันที่ และหน่วย** ให้เขียนเป็นคำอ่าน เพราะสคริปต์ปิด text normalization ของโมเดลไว้ตามค่าเริ่มต้น
- **สัญลักษณ์** ให้เขียนเป็นคำอ่าน เช่น `@` เป็น `แอท`
- **ชื่ออังกฤษ** ลองใช้ตัวสะกดอังกฤษก่อน ถ้าอ่านผิดจึงค่อยสะกดเป็นไทย จากงานจริง `GPT`, `Gemini`, `Codex` และ `AI` สะกดอังกฤษแล้วอ่านถูก แต่ `Copilot` อ่านผิด จึงเปลี่ยนเป็น `โคไพล็อต` และ `Claude Code` ใช้ `คล้อดโค้ด`
- **แยกซับกับบทพากย์** ข้อความที่ขึ้นจอและข้อความที่ส่งให้โมเดลจะต่างกันเมื่อมีการสะกดตามเสียง จึงควรเก็บไว้คนละที่

### 3. สร้างหลาย take

```bash
# Hi-Fi: เสียงใกล้ต้นแบบที่สุด
$VOX $SKILL/scripts/synth.py --lines script.txt --ref voices/narrator.wav --out takes

# Clone + คำสั่ง: ใส่อารมณ์ทุกบรรทัด (คำสั่งต้นบรรทัดจะถูกต่อท้ายคำสั่งนี้)
$VOX $SKILL/scripts/synth.py --lines script.txt --ref voices/narrator.wav --no-transcript \
    --style "warm, gentle bedtime storytelling tone, slow" --out takes_warm

# สร้างใหม่เฉพาะบรรทัด 2 และ 5 (take ของบรรทัดอื่นใน takes.json ยังอยู่)
$VOX $SKILL/scripts/synth.py --lines script.txt --ref voices/narrator.wav --out takes --only 2,5 --seeds 3,4
```

- ค่าตั้งต้นสร้าง 2 take ต่อบรรทัด (seed 7 และ 21) แต่ละ seed ได้จังหวะและน้ำเสียงต่างกัน จึงต้องเลือกจากการฟัง
- ไฟล์ที่ได้ชื่อ `s<บรรทัด>_seed<seed>.wav` และมี `takes.json` บันทึกว่าแต่ละไฟล์ส่งข้อความอะไรไปและใช้เวลาเท่าไร
- ระหว่างรัน สคริปต์พิมพ์ความยาว เวลาที่ใช้ RTF และจำนวนตัวอักษรต่อวินาทีของแต่ละ take เพื่อใช้ดูจังหวะ

### 4. ตรวจด้วย Whisper แล้วฟังเอง

```bash
$ASR $SKILL/scripts/check_takes.py --lines script.txt takes/*.wav
```

สคริปต์แสดง CER ของทุก take และ take ที่ CER ต่ำสุดในแต่ละบรรทัด ในงานจริง take ที่ใช้ได้มี CER อยู่ระหว่าง 0 ถึง 0.05 แต่ CER เป็นแค่ตัวช่วยคัดกรอง ไม่ใช่คำตัดสิน

- ตัวสะกดที่ไม่ตรงกันทำให้ CER สูงขึ้นทั้งที่อ่านถูก เช่น Whisper เขียน `ลิงค์` แต่สคริปต์เขียน `ลิงก์` หรือคำที่สะกดตามเสียงอย่าง `โคไพล็อต` ซึ่ง Whisper มักเขียนเป็นภาษาอังกฤษ
- Whisper เองก็มีอคติ เช่น ได้ยิน "Claude Code" เป็น "Cloud Code" ทั้งที่โมเดล TTS อ่านถูก
- CER จับวรรณยุกต์ที่เพี้ยนไม่ได้ จึงต้องฟังเองเสมอ โดยเฉพาะวรรณยุกต์ ตัวเลข คำทับศัพท์ การหยุดกลางคำ และคำสั่งในวงเล็บที่อาจถูกอ่านออกเสียง

### 5. ตัดเสียงเงียบ ปรับจังหวะ และต่อไฟล์

```bash
# หนึ่งไฟล์ต่อบรรทัด สำหรับวางบน timeline ของวิดีโอ ได้ final/s1.flac, final/s2.flac, ...
python3 $SKILL/scripts/finish.py takes/s1_seed7.wav takes/s2_seed21.wav --out final

# ต่อเป็นไฟล์เดียวตามลำดับที่ระบุ เว้น 750 ms ระหว่างประโยค ช้าลงเป็น 0.90 เท่า และปรับความดังเป็น -16 LUFS
python3 $SKILL/scripts/finish.py takes/s1_seed7.wav takes/s2_seed21.wav \
    --join out/narration.m4a --gap-ms 750 --tempo 0.90
```

- ตัดเสียงเงียบหัวท้ายที่ -40 dB โดยเหลือเสียงเงียบไว้ 0.05 วินาทีที่หัวและ 0.08 วินาทีที่ท้าย
- `--tempo` ใช้ ffmpeg `atempo` ซึ่งเปลี่ยนความเร็วโดยไม่เปลี่ยนระดับเสียง และวรรณยุกต์ไม่เพี้ยน ไม่ควรตั้งต่ำกว่า 0.85
- เมื่อใช้ `--join` ค่า tempo จะมีผลกับช่วงเงียบด้วย เช่น `--gap-ms 750 --tempo 0.90` จะได้ช่วงเงียบจริงราว 830 ms
- ถ้าต้องเอาเสียงไปประกอบกับภาพ ดูวิธีวางเสียงตาม scene และยึดภาพกับคำได้ที่หัวข้อ "ประกอบกับภาพ" ด้านล่าง

## ค่าตั้งที่ใช้

| ค่า | ใช้ | เหตุผล |
|---|---|---|
| `cfg_value` | 2.0 | ค่าที่ใช้ตลอดทั้งงานเล่านิทานและงานคลิป |
| `inference_timesteps` | 10 | ความเร็วกับคุณภาพสมดุลกันดี |
| `load_denoiser` | False | ไม่ต้องโหลดโมเดลลดเสียงรบกวนเพิ่ม เพราะ reference ที่อัดในห้องเงียบสะอาดพออยู่แล้ว |
| `optimize` | False | ใช้ `torch.compile` ซึ่งใช้กับ MPS ไม่ได้ จะเปิดได้เฉพาะบน CUDA ด้วย `--optimize` |
| `normalize` | False (ค่าตั้งต้นของไลบรารี) | ให้เตรียมคำอ่านเองในสคริปต์ จะได้ควบคุมผลได้ |
| `retry_badcase` | True (ค่าตั้งต้นของไลบรารี) | ไลบรารีจะสร้างใหม่เองเมื่อความยาวเสียงผิดสัดส่วนกับความยาวข้อความ |
| seed | 7 และ 21 | ตั้งทั้ง `torch` และ `numpy` เพื่อให้รันซ้ำได้ผลเดิม |

## จังหวะการพูด

- VoxCPM2 ไม่มีพารามิเตอร์ความเร็ว มีสามวิธีที่ใช้คุมจังหวะ คือ จังหวะของ reference, ช่วงเงียบระหว่างประโยค และ `atempo` หลังสร้างเสียงเสร็จ
- **จังหวะเล่านิทานที่ผ่านการอนุมัติแล้ว** อยู่ที่ราว 8 ตัวอักษรไทยต่อวินาที ทำได้ด้วยการใช้ reference ที่พูดช้า สร้างเสียงทีละประโยค เว้นช่วง 750 ms และตั้ง `atempo` ที่ 0.90 (สำหรับงานที่ต้องช้ากว่านี้ เคยใช้ช่วงเงียบ 1200 ms กับ 0.85)
- คำสั่งอารมณ์ทำให้จังหวะเปลี่ยนมาก จากการทดสอบ ประโยคเดียวกันยาว 66 ตัวอักษร ใช้เวลาตั้งแต่ 4.0 ถึง 8.0 วินาทีแล้วแต่คำสั่ง ถ้าประโยคที่มีคำสั่งเร็วหรือช้าไปทั้งชุด ให้แก้ถ้อยคำของคำสั่งก่อน แล้วจึงค่อยปรับ `--tempo`
- VoxCPM2 กำหนดความยาวเสียงเป็นวินาทีไม่ได้ ถ้าต้องให้พอดีกับ scene ให้แก้สคริปต์ก่อน แล้วใช้ `--tempo` เป็นทางสุดท้าย

## คำสั่งอารมณ์ที่ทดสอบแล้ว

ถ้อยคำเหล่านี้มาจากการทดลองเมื่อ 11 ต.ค. 2026 กับประโยคภาษาไทย ใช้ cfg 2.0 และ 10 steps ผลคือทุก clip พูดครบประโยค และไม่มี clip ใดอ่านคำสั่งออกเสียง **แต่ยังไม่มีใครฟังตัดสินว่าแต่ละอารมณ์ฟังถูกต้องหรือไม่**

| อารมณ์ | ถ้อยคำที่ส่งให้โมเดล |
|---|---|
| อบอุ่น (ค่าตั้งต้นของงานเล่านิทาน) | `warm, gentle bedtime storytelling tone, slow` |
| ร่าเริง | `cheerful, bright and happy tone` |
| ตื่นเต้น | `very excited, energetic, slightly faster` |
| กระซิบ | `whispering softly, secretive` |
| เศร้า | `sad, slow, low voice` |
| ลุ้นระทึก | `tense, suspenseful, slow and quiet` |
| ประหลาดใจ | `surprised, amazed` |

- ตัวขยายจังหวะ (`slower`, `a little faster`) และระดับ (`subtle`, `strongly`) ยังไม่ได้ทดสอบ
- อย่าใส่คำบอกความเร็วไว้ในคำสั่งอารมณ์ ถ้าตั้งใจจะใช้คู่กับคำบอกความเร็วอีกตัว เช่น `warm` ที่มีคำว่า slow อยู่แล้ว เมื่อใช้คู่กับ fast จะกลายเป็นคำสั่งที่ขัดกันเอง
- คำสั่งควรบอกว่า "พูดอย่างไร" ไม่ใช่ "ใครพูด" ถ้าเขียนว่า "a young girl..." เสียงจะเปลี่ยนเป็นคนอื่น
- อารมณ์ที่ได้ต่างกันไปในแต่ละ take ควรฟังหลาย take ก่อนตัดสิน

## ประกอบกับภาพ

วิธีนี้ใช้ทำคลิป 45 วินาทีที่มี 6 scene

1. วางแต่ละประโยคที่ต้น scene บวก 0.25 วินาที (ประโยคแรกที่ 0.6 วินาที) และตั้งความยาว scene ให้เสียงจบก่อนเปลี่ยน scene อย่างน้อย 0.2 วินาที
2. ใช้ `check_takes.py --words final/s*.flac` เพื่อหาเวลาของคำ แล้วยึดภาพให้ขึ้นก่อนคำราว 0.08 วินาที คำภาษาไทยจะออกมาเป็นชิ้นย่อยระดับตัวอักษร ส่วนคำอังกฤษจะออกมาเป็นคำเต็ม จึงยึดภาพกับชื่ออังกฤษได้ง่ายกว่า
3. รวมเสียงทั้งหมดเป็นไฟล์เดียว ปรับความดังเป็น -16 LUFS แล้วเข้ารหัสเป็น AAC 192k stereo ก่อนรวมกับวิดีโอด้วย `ffmpeg -map 0:v -map 1:a -c copy -shortest`

## ความเร็วและทรัพยากร (M5 Max, MPS)

| รายการ | ค่าที่วัดได้ |
|---|---|
| เวลาโหลดโมเดล | ราว 60 วินาทีเมื่อเปิดเครื่องใหม่ และ 5–10 วินาทีเมื่อไฟล์อยู่ใน cache ของระบบแล้ว สคริปต์โหลดโมเดลครั้งเดียวแล้วสร้างทุกบรรทัดในการรันเดียว |
| RTF | ราว 0.6 สำหรับ clip ยาว และ 0.65–0.9 สำหรับประโยคสั้น 2–4 วินาที |
| เวลาต่อ clip | 16–28 วินาที สำหรับ clip ยาวระดับ scene ของนิทาน |
| หน่วยความจำ | สูงสุดราว 14 GB (weights เป็น bf16 แต่ถูกแปลงเป็น fp32 บน MPS) |
| CUDA | การ์ดจอ RTX 4090 ได้ RTF ราว 0.30 และใช้ VRAM ราว 8 GB ตัวเลขนี้มาจาก model card ยังไม่ได้ทดสอบเอง |
